# 底部滚动、复制与 Markdown 可视化设计

创建时间：2026-09-07  
功能：精确对齐最新内容、支持详细对话选择复制，并补齐 Markdown 表格等视觉结构。  
目的：消除项目级滚动造成的底部空白和跳步，同时提升长技术回复的阅读与复用效率。

## 现状与根因

1. `MessageList` 使用 `VirtualizingPanel.ScrollUnit="Item"`。WPF 以整条消息为偏移单位，最后若由多条短消息组成，视口底部无法继续移动到内容实际底边；轻微上滑又可能跨过一条很高的消息。
2. 自动跟随只执行 `ScrollIntoView(lastItem)`，它只保证末项可见，不保证末项底边与视口底边对齐。
3. Markdown 正文由多个 `TextBlock` 构成。`TextBlock` 不支持鼠标选区，因此除代码块外无法复制。
4. 当前解析器逐行输出文本，不识别 Markdown 表格分隔行，导致 `|---|` 等源码直接显示。

## 方案对比

### 底部滚动

- 推荐：保留 `Standard` 虚拟化和一页缓存，将单位改为 `Pixel`；自动跟随在布局稳定后对内部 `ScrollViewer` 执行 `ScrollToEnd`。优点是底边精确、微量滚动连续；风险是可变高度项可能修正范围，需用真实大会话双帧验收。
- 保留项目滚动并增加底部占位：只能掩盖空白，无法解决轻微滚动跨过高消息，不采用。
- 关闭虚拟化：滚动范围精确，但 121 MB 会话会创建全部视觉树，不采用。

### 复制与 Markdown

- 推荐：将 `MarkdownTextBlock` 的内部承载改为只读 `RichTextBox` 与 `FlowDocument`。它原生支持鼠标跨段选择和 `Ctrl+C`，并能用 `Paragraph`、`List`、`Table` 表达 Markdown 结构。
- 为每行换成只读 `TextBox`：只能逐行选择，且会丢失行内粗体和代码样式，不采用。
- 引入第三方 Markdown 控件：能力完整但违反无其他依赖约束，不采用。

## 组件设计

### 精确滚动

- `MessageList` 使用像素滚动，继续启用 `Standard` 虚拟化、页缓存和禁用容器回收。
- `ScrollToBottomIfNeeded` 在后台调度中先 `ScrollIntoView` 生成末项，再在渲染优先级获取内部 `ScrollViewer` 并调用 `ScrollToEnd`。
- “回到最新”沿用同一路径，不维护第二套逻辑。
- 滚动 QA 改用像素目标：底部、上移 80 px、上移 320 px、下移 160 px、回到底部。
- 新增底部空白测量：末条可见项底边与消息视口底边差值不超过 2 DIP；上移 24 px 后偏移变化应接近 24 px，而不是整条消息高度。

### 可选择 Markdown

- `MarkdownTextBlock` 保持现有公开依赖属性，内部改为单个无边框、透明、只读的 `RichTextBox`。
- `FlowDocument` 关闭分页列宽，边距为零；颜色、字号和字体继续随现有绑定同步刷新。
- 选择不触发消息切换，不启用编辑、粘贴或拖放；保留系统复制快捷键。
- 流式阶段继续以 40 ms 合并刷新，结束时同步生成最终文档。

### Markdown 视觉规则

- `#`、`##`、`###`：分级字号和半粗体。
- `**粗体**`、行内代码：保留现有行内样式。
- 无序/有序列表：使用 FlowDocument 列表或带明确缩进的列表段落。
- 围栏代码块：等宽字体、深色背景、内边距。
- `>` 引用：左侧强调线与次级文字色。
- `---` 分隔线：主题边框色横线。
- Markdown 表格：识别表头行、合法分隔行和后续数据行；表头使用较深背景，单元格有统一边框和内边距，文字可参与选择复制。
- 不执行 HTML、脚本或外链内容，只渲染本地文本结构。

## 验收标准

1. 点击“回到最新”后最后一条内容底边与视口底边差值不超过 2 DIP，不出现大块假空白。
2. 从底部上移 24 px 后偏移连续变化，最新内容底部不会因整项跳步立即消失。
3. 普通段落、标题、列表、代码、表格文字均可由只读 RichTextBox 选择并复制；控件不可编辑。
4. Markdown 表格不再显示原始 `|---|` 分隔行，表头和单元格边界清晰。
5. 121 MB、1251 项真实会话的方向、双帧稳定、响应、阅读意图、返回最新和固定滑块测试全部通过。
6. Release 构建 0 警告、0 错误，版本升级为 1.2.0 并生成自包含 ZIP。

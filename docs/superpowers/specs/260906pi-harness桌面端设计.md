# PI-Harness 桌面端设计规格

- 日期：2026-09-06
- 状态：已经用户确认
- 目标平台：Windows 10/11 x64

## 1. What：产品目标

PI-Harness 是一款本机桌面端 pi 会话管理器。它以类似 Codex 桌面端的简洁两栏布局，自动发现本机 pi 项目和会话，支持选择项目文件夹创建对话，也支持继续已有对话。

产品只依赖用户已安装并配置的 pi。不依赖 pi-dashboard，不启动 HTTP/WebSocket 服务，不要求用户另行安装 .NET 运行时。交付形式为自包含的文件包，用户解压后可直接运行 `PI-Harness.exe`。

## 2. Why：技术选择

实现采用 C# / WPF / .NET 10，原因如下：

- WPF 能以 Windows 原生控件实现简洁的项目树和聊天界面。
- .NET 对子进程、异步标准输入/输出和 JSONL 有稳定的标准库支持。
- 采用自包含发布后，用户无需安装 .NET。
- 不引入第三方 NuGet 包，减少供应链和版本风险。

未选用方案：

- C++17 / Win32：交付体积更小，但聊天排版、流式更新和异步 RPC 的开发与维护成本明显更高。
- Qt：动态部署会带入多个 DLL，静态部署需要额外构建与授权考量，本项目没有必要承担这些成本。
- Electron：能快速实现界面，但交付包过大，且引入 Chromium/Node 运行组件。

## 3. How：整体架构

应用按职责划分为五个单元：

1. `SessionCatalog`：扫描和监视 pi 会话目录，输出按工作目录分组的会话摘要。
2. `SessionParser`：逐行容错解析 JSONL，提取会话头、名称、首条用户消息和最后活动时间。
3. `PiProcessLocator`：在 `%APPDATA%\npm\pi.cmd` 和 `PATH` 中查找 pi，并返回可执行的启动信息。
4. `PiRpcClient`：管理单个 pi RPC 子进程，实现请求关联、事件分发、流式输出、中止和可控的进程回收。
5. `MainViewModel` 与 WPF 视图：展示项目树、聊天记录、输入框和中文状态/错误信息。

第一版保持单活动 RPC 会话。pi 正在生成时，禁止切换会话；用户可等待完成或先点击“停止”。这避免后台子进程无限累加，也使应用关闭和异常恢复行为确定。

## 4. 左侧项目与会话树

左侧使用两级树，不使用项目卡片、会话胶囊、消息预览或插件标记。

```text
新对话
────────────────
项目文件夹 A
  会话标题 1
  会话标题 2

项目文件夹 B
  会话标题 3
```

具体行为：

- 启动时扫描 `%USERPROFILE%\.pi\agent\sessions`。
- 以 JSONL 首行会话头中的 `cwd` 为真实分组依据，不反解编码后的目录名。
- Windows 路径比较不区分大小写，避免同一项目重复分组。
- 文件夹栏目显示路径最后一级名称，鼠标悬停显示完整路径。
- 会话标题优先使用最新 `session_info.name`，其次使用第一条用户文本，最后使用创建时间。
- 标题显示为单行并做省略，悬停显示全文。
- 项目按最近会话活动时间倒序，项目内会话也按最近活动时间倒序。
- 只有 `.meta.json` 而没有 JSONL 的空壳记录不显示。
- 使用 `FileSystemWatcher` 触发延迟合并刷新，避免一次写入造成多次重复扫描。

## 5. 聊天界面

右侧为聊天主区：

- 顶部显示会话标题、项目完整路径、当前模型和运行状态。
- 中部显示用户消息、助手回复、思考内容、工具调用和工具结果。
- 思考和工具记录使用弱化样式，不与最终回复争夺视觉焦点。
- 支持标题、列表、粗体、行内代码和代码块等常用 Markdown 显示；不执行 HTML。
- 底部为多行输入框、发送按钮和停止按钮。`Ctrl+Enter` 发送，`Enter` 换行。
- 正常接收新内容时自动滚动到底部；用户主动向上查看时不强制抢回底部。

## 6. 新建与继续对话

### 6.1 新建对话

1. 用户点击“新对话”。
2. 系统显示 Windows 文件夹选择器。
3. 用户选择项目文件夹。
4. 应用以该文件夹作为子进程 `WorkingDirectory`，启动 `pi --mode rpc --approve`。
5. 在首次用户消息持久化后，新会话自动出现在对应项目下。

### 6.2 继续对话

1. 用户点击已有会话。
2. 应用以会话头的 `cwd` 作为工作目录，通过 `pi --mode rpc --approve --session <jsonl路径>` 启动子进程。
3. 应用发送 `get_state` 和 `get_messages`，恢复当前有效分支、模型和历史消息。
4. 新消息通过 `prompt` 命令发送，由 pi 写回原会话文件。

## 7. RPC 协议与进程生命周期

- 发送和接收均使用 LF 分隔的 UTF-8 JSONL。
- 每个请求使用唯一 `id`，以匹配 `response`。
- stdout 中无法解析为 JSON 的普通日志要单独记录或忽略，不得导致 RPC 客户端中断。
- 未识别的扩展事件要忽略并保留诊断信息，不得导致界面崩溃。
- 进程启动失败、请求超时、进程意外退出和 pi 返回错误时，界面显示中文错误信息。
- 用户停止生成时发送 `clear_queue` 后再发送 `abort`。
- 切换会话、创建新对话或关闭应用时，先请求 RPC 子进程正常结束；超时后只终止由 PI-Harness 创建的进程树。
- 不读取、复制或保存 API Key，认证完全沿用 pi 已有配置。

## 8. 性能与稳定性

- 会话扫描和 JSONL 解析在后台任务中执行，不阻塞 UI 线程。
- 扫描时只提取索引所需的字段，不将全部历史消息长期保留在侧边栏模型中。
- `FileSystemWatcher` 事件使用合并延迟，限制刷新频率。
- 聊天记录使用 WPF UI 虚拟化或分段增量更新，不在每个 token 到达时重建全部视图。
- 可观察集合、诊断日志和异常缓存设置明确上限，禁止无限累加。

## 9. 错误处理

- pi 未找到：保留会话浏览能力，禁用发送，显示可操作的安装/路径提示。
- 单个 JSONL 损坏：跳过该会话并记录文件路径，其他会话继续加载。
- 项目目录不存在：会话仍可浏览，但禁止启动 RPC，显示“项目路径不存在”。
- RPC 超时或退出：所有等待中请求统一失败，UI 恢复为可重试状态。
- 模型/API 错误：显示 pi 的错误文本，但对可能的密钥字段做脱敏。
- 目录监视失效：保留手动刷新按钮，同时定期进行低频校验。

## 10. 第一版功能边界

第一版包含：

- 项目/会话自动发现与两级展示。
- 选择项目文件夹创建对话。
- 打开并继续已有对话。
- 文字消息、流式助手内容、思考、工具调用和错误状态显示。
- 手动停止生成。
- 自包含 Windows x64 Release 发布包。

第一版不包含：

- 图片或其他附件上传。
- 模型选择、思考等级切换。
- 会话删除、重命名、导出、分叉树编辑。
- 多会话并行生成。
- 远程机器、多用户或 pi-dashboard 集成。

## 12. Git 开发流程

- 仓库使用 `main` 分支。
- 每个提交对应一个可独立理解、可独立验证的开发节点。
- 不将 `bin/`、`obj/`、发布包、运行日志或本机测试数据提交进仓库。
- 每次提交前执行该节点相关测试，并检查实际 diff。
- 不使用破坏性 Git 命令覆盖用户工作。
- 最终交付时保持工作树清洁，并提供节点提交列表。

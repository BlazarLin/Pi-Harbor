# PI-Harness 详细会话渲染性能实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让大型 pi 会话的右侧文字历史快速出现且可流畅滚动，同时保留后台 pi 上下文和继续对话能力。

**Architecture:** Core 层流式读取 JSONL 并沿最后活动叶节点还原当前分支，只产生轻量显示项；App 层并行加载本地历史与 pi 状态，以单次集合 Reset 提交到 WPF，并合并自动滚动调度。正常打开已有会话不再调用 RPC `get_messages`。

**Tech Stack:** C# 14、.NET 10、WPF、System.Text.Json、现有无第三方依赖测试程序。

## Global Constraints

- 不新增第三方依赖，不修改 pi 会话文件。
- 保持用户、助手、思考、工具文字以及压缩摘要的活动分支语义。
- 图片 Base64 不进入显示模型。
- pi 未完成后台初始化前禁止发送，但界面必须保持响应。
- 新代码文件包含创建日期、功能与目的说明。

### Task 1: 本地轻量活动分支读取器

**Files:**
- Create: `src/PIHarness.Core/Sessions/SessionHistoryReader.cs`
- Modify: `src/PIHarness.Core/Models/ChatModels.cs`
- Create: `tests/PIHarness.Tests/SessionHistoryReaderTests.cs`
- Modify: `tests/PIHarness.Tests/Program.cs`

**Interfaces:**
- Consumes: pi JSONL 的 `id`、`parentId`、`type`、`message` 字段。
- Produces: `SessionHistoryReader.ReadAsync(string, CancellationToken)` 与 `SessionHistorySnapshot.Items`。

- [ ] **Step 1: 写失败测试**

建立含主分支、废弃分支、损坏行和图片数据的临时 JSONL。断言读取结果沿最后叶节点回溯，只包含活动分支，保留文字项且所有 `SessionHistoryItem.Text` 均不包含图片 Base64 标记。

- [ ] **Step 2: 运行测试并确认失败**

Run: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-tests.ps1`

Expected: 编译失败，提示 `SessionHistoryReader` 或 `SessionHistorySnapshot` 不存在。

- [ ] **Step 3: 实现最小读取器**

逐行使用 `StreamReader.ReadLineAsync` 与 `JsonDocument.Parse`，每次解析后立即释放文档。为每个带 id 的条目保存轻量节点：

```csharp
private sealed record HistoryNode(string Id, string? ParentId, IReadOnlyList<SessionHistoryItem> Items);
```

最后一个合法 id 作为活动叶节点，沿 `ParentId` 回溯并反转。映射规则与现有 `MapMessage` 一致；内容数组只读取 `type == "text"`，不访问图片 `data`。

Run: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-tests.ps1`

Expected: 新增读取器测试和既有 20 项测试全部通过。

- [ ] **Step 3: 实现批量替换和并行加载**

`ReplaceAll` 直接操作受保护的 `Items`，完成后依次触发 Count、索引器和一次 Reset。`OpenSessionAsync` 在启动 pi 前创建本地读取任务；`StartRpcAsync` 并行等待历史与 `get_state`，先把历史映射为 `ChatItemViewModel` 并批量提交，再在状态响应完成时进入 Ready。删除正常路径中的 `get_messages` 请求。

`MainWindow` 保存唯一待执行的 `DispatcherOperation`，重复滚动请求只复用它。集合 Reset 时解绑此前订阅，避免旧消息继续触发滚动。

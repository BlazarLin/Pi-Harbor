# Pi Harbor Ubuntu 兼容性评估（1.8.0 之后）

> 结论先行：**Core 层已经可以跨平台运行**（net10.0 纯 .NET，无 Windows 依赖），可以直接在 Ubuntu 上跑会话解析、搜索、用量统计、fake RPC 与全部 Core 测试；**WPF UI 层无法在 Linux 运行**，需要 UI 框架迁移才能交付 Ubuntu 桌面版。这是一次中等规模的迁移（预计 2~3 周），不是重写。

## 1. 现状盘点（1.8.0 代码）

| 层 | 目录 | Linux 可用性 |
| --- | --- | --- |
| Core（发现/解析/搜索/用量/管理存储/RPC 客户端） | `src/PIHarness.Core` | ✅ 完全可用（`net10.0`，仅 BCL 依赖） |
| 测试套件 | `tests/PIHarness.Tests` | ✅ 大部分可用（个别用例断言 XAML 源码/注册表，需按平台跳过） |
| App（WPF 视图/视图模型） | `src/PIHarness.App` | ❌ WPF 仅限 Windows |

Core 里的 RPC 客户端通过 `PiProcessLocator`（找 `pi.cmd`）启动 pi；Linux 上 pi 的入口是 `pi`（npm bin 脚本），需要平台分支。

## 2. App 层的 Windows 专属清单（迁移时必须替换）

- WPF 窗口/绑定/模板：整体迁移到 **Avalonia UI**（XAML 方言接近，`Binding`/`Style`/模板概念一致；`HierarchicalDataTemplate` → `TreeDataTemplate`，`x:Static`/资源查找细节需调整）。
- DWM 暗色标题栏（`DwmSetWindowAttribute`）→ Avalonia `ExtendClientAreaToDecorativesHint` / 主题。
- 任务栏角标（`TaskbarItemInfo.Overlay`）→ Linux 下无统一任务栏 API，用托盘图标角标替代或忽略。
- Windows 通知（Toolkit Toast）→ Linux 用 `org.freedesktop.Notifications`（DBus，社区库 `Tmds.DBus` 或通知守护进程命令行）。
- 托盘（WinForms NotifyIcon）→ Avalonia `TrayIcon`（内置，跨平台）。
- 全局热键（RegisterHotKey）→ Linux 无系统级 API，X11 方案复杂，建议先降级为应用内快捷键。
- 窗口闪烁（FlashWindowEx）→ Linux 用 `set_urgent`（X11 hint）或忽略。
- Markdown 渲染（自研 `MarkdownTextBlock`，基于 WPF FlowDocument）→ 迁移到 Avalonia 版本或改用 HtmlLabel/WebView。

## 3. 建议路线

1. **第一步（低成本，先行）**：把 `tests` 中断言 XAML 源码的用例（StartupSidebarStyleTests、ConversationUiContractTests、ScrollQaContractTests、部分 ProductExperienceTests）标注 `[SkipOnLinux]`，让 Core + 其余测试在 Ubuntu CI 跑起来。这一步验证数据层 100% 跨平台。
2. **第二步**：抽出 `IUiServices`（通知/托盘/热键/角标/剪贴板/文件对话框）接口，Windows 实现保留，为 Avalonia 实现留位。
3. **第三步**：新建 `src/PIHarness.Avalonia`，复用全部 ViewModels（`ObservableObject`/命令/集合无 WPF 依赖），逐窗口迁移：主窗口 → 设置窗口 → QA 适配。
4. **打包**：Avalonia 支持 `dotnet publish -r linux-x64` 自包含；可选 .deb/.AppImage。

## 4. 风险与工作量

- `MarkdownTextBlock` 是最大单点（自研渲染器约千行，深度依赖 WPF 文档对象）：迁移代价最高，可选方案是 Avalonia 下改用 `HtmlRichTextBlock` 或轻量 Markdown→Avalonia Inline 转换。
- QA 截图流程（RenderTargetBitmap）在 Avalonia 有对应 API，但 ScrollQA 的亚像素断言需要重校准。
- 总体估计：核心迁移 2~3 周 + Markdown 渲染器 1~2 周 + QA 重建 1 周。

## 5. 不迁移 UI 的替代方案

如果 Ubuntu 需求只是"能看、能搜、能继续对话"，可以先用 **终端 TUI**（复用 Core，输入用 pi 本体）覆盖；桌面级体验则必须走 Avalonia 迁移。

## 6. 落地状态（1.9.0）

以下工作已在 Ubuntu 24.04 x64 上完成并复验：

| 项目 | 结果 |
| --- | --- |
| Core / ViewModels | 纯 `net10.0`，无 Windows 依赖；`SessionCatalog` 兼容另一平台记录的反斜杠 `cwd` |
| Pi 启动 | `PiProcessLocator` 走 Unix 分支，按 PATH 查找 `pi` 后直接 exec；GUI 启动时 PATH 过短则由 `~/.pi/agent/bin` 等固定目录兜底 |
| 前端 | `src/PIHarness.Avalonia` 可运行，窗口、会话列表、正文渲染、附件与设置复用 ViewModels |
| 测试 | `scripts/run-tests.sh`：81 项中 80 通过，1 项 Windows 专属用例按 `[PlatformOnly("windows")]` 跳过 |
| 打包 | `scripts/build-release-linux.sh` 生成自包含目录、`Pi-Harbor-linux-x64.tar.gz` 与 `pi-harbor_<版本>_amd64.deb` |
| 本地安装 | `scripts/install-linux.sh --dock` 安装到 `~/.local`，生成 `pi-harbor.desktop` 并加入 GNOME 快捷启动栏 |
| 桌面集成 | X11 `WM_CLASS` 固定为 `pi-harbor`，与 `.desktop` 同名，运行中窗口可归到同一个启动图标 |

仍未覆盖：系统通知、任务栏角标、全局热键、“在文件资源管理器中打开”（Linux 前端暂无入口）。这些能力依赖 Windows API，Avalonia 前端按设计降级为侧栏未读与窗口标题提示。

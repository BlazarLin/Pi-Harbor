# Pi Harbor 1.3.0 输入体验与产品完善

## 本轮交付

本轮针对 1.2.1 的文字输入区完善完整发送流程：输入 → 引用文件/选择 skill → 添加和检查图片 → 发送 → 失败恢复。

- 显式使用亮色 `CaretBrush`，继续遵循 Windows 的系统闪烁设置；会话切换与发送完成后恢复输入焦点。
- `@` 根据当前项目异步查找文件，120 ms 防抖、取消过期查询，插入带引号的相对路径引用。路径引用由模型按需读取，不在发送时自动读取或上传文件。
- `/` 只在消息开头出现时提供命令菜单，来源为当前 Pi 的 `get_commands`；支持扩展、提示模板及 `/skill:名称`，不伪造不可用的终端命令。
- 鼠标、上下键、Tab/Enter 和 Esc 操作补全；中文输入法组词时不抢占候选确认键。
- 图片支持剪贴板位图、复制的图片文件和文件选择器；统一 PNG 编码，发送到 RPC `images` 字段；输入区与本次发送的消息均可点击预览。
- 附件数量、编码大小和像素数量有上限；删除附件不影响文字；纯图片消息可发送。
- 会话草稿在本次进程内隔离保存，发送被接受前暂时锁定输入以避免覆盖；发送未确认时保留草稿，显示重新连接入口，不自动重发造成重复请求。
- 无 agent 生成事件的扩展命令会查询运行状态，避免永远显示“正在处理”。
- 会话启动前立即锁定切换，避免异步回收窗口期重复启动；已打开的空会话显示正确的输入引导。
- 历史纯图片用户消息保留轻量附件提示，继续避免 Base64 进入界面模型。

协议依据：[Pi 官方 RPC 文档](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/rpc.md)，并与本机 `@earendil-works/pi-coding-agent` 0.84.3 的 `docs/rpc.md` 对照。图片使用 `type/data/mimeType`，命令由 `get_commands` 返回。

## 验收方法

- 自动测试包含补全边界、文件扫描排除与取消、失败草稿保留、会话草稿隔离、扩展命令状态恢复、图片 JSONL 协议往返和历史图片占位。
- `scripts/build-release.ps1` 完整测试、自包含 Release 发布、启动截图与 ZIP 打包。
- `--qa-composer-capture-dir` 启动真实 Pi，强制 `--no-session --offline`，不发送模型请求；验证输入框焦点、亮色光标与静置多帧闪烁、真实项目文件和命令菜单、Esc、WPF 粘贴事件、图片编码/预览/移除、数量限制、纯图片消息、普通文本粘贴，以及最小窗口布局。
- 图片协议由伪 RPC 子进程验证；尚未调用付费模型进行图片理解测试。中文输入法有组合输入保护，但仍需人工覆盖不同 IME 的候选交互。

## 后续逐步完善

| 优先级 | 当前缺口 | 下一步与验收标准 |
|---|---|---|
| P1 | 草稿重启后不恢复 | 本地持久化文本和受控附件缓存，原子写入、过期清理；异常退出重启仍能恢复对应会话草稿 |
| P1 | 历史原图不能预览 | 按消息定位按需读取图片、限制缓存；大型 JSONL 首次打开时间和内存不回退 |
| P1 | 模型能力与错误恢复信息不足 | 识别模型 `input` 类型、在发送前提示图像能力；展示可行动的认证/限额/连接错误与重试状态 |
| P1 | 扩展需要表单时缺少 RPC UI 支持 | 实现 `extension_ui_request` 的选择、确认、输入与取消，不支持的请求明确返回取消，不能悬挂 |
| P2 | 大项目文件搜索覆盖有限 | 尊重 `.gitignore`、增量索引与模糊排序，显示截断状态；超大目录键入仍流畅 |
| P2 | 会话定位和管理不足 | 搜索、重命名、导出、可撤销归档；活动会话切换和草稿归属保持正确 |
| P2 | 长任务状态不够清楚 | 分离启动、请求接受、生成、工具执行与断线状态，提供队列和耗时反馈 |
| P2 | 产品交付与可访问性 | 高 DPI、多种中文 IME、键盘全流程、安装升级与迁移测试，建立固定验收清单 |

本轮保持单会话生成范围。上述待办未标记为已实现，适合按独立可验收节点继续推进。
